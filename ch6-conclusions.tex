\chapter{Conclusions}

The thesis presented a framework for running TOTP applications on USB sticks, without breaking the MFA aspect.
The framework had security as number one priority: it considered different attack scenarios, and made them impossible/ hard to pull off.
\app{}, a ready-to-use application developed both for Linux and Windows, proved that the framework can be put in practice.
Both the framework and the implementation were documented.
The design decisions were reasoned through bibliographic research.
Digital security recommendations of trusted institutions were taken into account.
The application was manually tested on virtual machines, and automatically tested with unit tests.
The source code is publicly available on GitHub, at \url{https://github.com/broland29/authenstickator}.

All in all, coming up with one such framework was fun in a way.
I was really happy when I got the idea to make TOTP code generation on USB devices, and I saw that it has not been done before.
But I won't pretend that it wasn't extremely hard: I had to change the ideas many times, rethink flows, start over.
What looked like a great idea at first often got completely annihilated by one little flaw.
In my opinion, this is why cybersecurity is hard: you have to be extremely cautious and think of virtually all scenarios\dots and the attacker has to find just one mistake.

As further improvement, TPM support for Windows could be implemented.
This was not done due to lack of time and lack of available documentation.
Although TPM has been around for some time, the development experience with it feels like a burden: no clear documentation, no well-documented APIs, no examples to be found on the internet.
The current Linux code is the result of lots of trial and error, not of a smooth development.

\app{} breaks the misconception that authenticator apps need a mobile device or specialized hardware.
It shows that cybersecurity concepts can still be mixed to come up with new security solutions.
You can still opt for open source products, or develop your own, if you lose trust in closed source mainstream applications.
If I could do it, you can too!
